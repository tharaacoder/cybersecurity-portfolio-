تصميم شبكة مؤسسة موزّعة بفرعين مع سياسات أمنية 
## (OSPF + VLANs + GRE + HSRP + ACLs)

## الهدف
تصميم وربط فرعين جغرافيًا منفصلين عبر ISP وGRE Tunnel، مع تقسيم 
كل فرع لـ VLANs متعددة، توفير Redundancy عبر HSRP، وتطبيق سياسات 
أمنية دقيقة عبر ACLs للتحكم بحركة البيانات بين الشبكات.

## الأدوات
Cisco Packet Tracer

## بنية الشبكة

### الفرع الأول (يسار)
- 6 VLANs: 30, 40, 50, 60, 70, 80 — كل واحد بشبكة فرعية خاصة 
  ضمن 172.16.x.0/24
- VTP Server/Client لإدارة VLANs مركزيًا عبر السويتشات
- LACP وPAgP لتجميع الروابط (Link Aggregation) بين السويتشات لزيادة 
  النطاق الترددي والموثوقية
- خوادم DNS وCCNA مخصصة

### الفرع الثاني (يمين)
- VLAN 10 (192.168.10.0/24) وVLAN 20 (192.168.20.0/24)
- بنية Multilayer Switching مع سويتشات 3560-24PS متعددة ومترابطة 
  بروابط زائدة (Redundant Links) لضمان الاستمرارية
- خادم DHCP مركزي

### الربط بين الفرعين
- كل فرع يتصل بـ ISP عبر راوتر منفصل (R1, R2) بشبكات نقطية 
  (100.0.0.0/30, 200.0.0.0/30)
- GRE Tunnel (192.168.100.0/30) يربط الفرعين مباشرة فوق البنية 
  التحتية لـ ISP، محاكيًا اتصال WAN آمن بين مواقع الشركة

## الخطوات
1. صممت الطوبولوجيا الكاملة وقسّمت كل فرع حسب VLANs المطلوبة
2. فعّلت OSPF على كل الراوترات لتبادل جداول التوجيه ديناميكيًا 
   بين الفروع
3. أعددت VTP لتوحيد إدارة VLANs عبر سويتشات الفرع الأول
4. جهّزت GRE Tunnel لربط الفرعين عبر شبكة ISP الوسيطة
5. طبّقت HSRP على السويتشات متعددة الطبقات (Multilayer Switches) 
   بالفرع الثاني لتوفير Gateway احتياطي و Load Balancing بين 
   المسارات
6. كتبت ACLs لتطبيق 3 سياسات أمنية محددة:
   - منع الاتصال الكامل بين 172.16.50.0 و192.168.10.0
   - منع أي جهاز من عمل ping لخادم DHCP (حماية الخادم من الفحص 
     المباشر)
   - حصر اتصال 192.168.20.0 بحيث يوصل فقط لخدمتي DNS وHTTP 
     على الخوادم، ومنع أي وصول آخر

## النتيجة
شبكة موزعة تعمل بكفاءة بين فرعين، مع توجيه ديناميكي عبر OSPF، 
اتصال WAN آمن عبر GRE، توفر عالي عبر HSRP، وتطبيق سياسات أمنية 
دقيقة على مستوى الشبكة عبر ACLs — مما يحاكي بيئة مؤسسية حقيقية 
تجمع بين الأداء والأمان.

## الدروس المستفادة
أصعب تحدي كان إعداد HSRP مع Load Balancing على السويتشات متعددة 
الطبقات. تحديدًا واجهت لخبطة بالتفريق بين وظائف Layer 2 وLayer 3 
وأيهم لازم يشتغل ك Gateway ويتعامل مع التوجيه كان يحتاج وضوح أكبر بالبداية. 
بعد ما فهمت الفرق صح، صار سهل أضبط HSRP والـ priorities بشكل منطقي 
بين السويتشات
