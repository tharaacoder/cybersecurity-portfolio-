# تصميم وتوجيه شبكة فرعية متعددة الأقسام (Subnetting + Static Routing)

## الهدف
تقسيم شبكة 172.16.0.0 إلى subnets بأحجام مختلفة (VLSM) لتغطية 
ثلاثة أقسام بأعداد مستخدمين متفاوتة، وربطها مع بعض ومع خدمات 
مركزية (DNS، إنترنت خارجي) عبر Static Routing.

## الأدوات
Cisco Packet Tracer

## بنية الشبكة

### الفروع الثلاثة (VLSM subnetting)
| الفرع | الشبكة | عدد الأجهزة |
|---|---|---|
| الفرع الأول | 172.16.1.0/26 | 50 Host |
| الفرع الثاني | 172.16.0.128/25 | 62 Host |
| الفرع الثالث | 172.16.0.0/25 | 100 Host |

كل فرع يحتوي سويتش + 3 أجهزة PC، ومربوط براوتر مخصص له.

### الربط المركزي
- راوتر مركزي (R) يوزّع الثلاث فروع عبر شبكات نقطية:
  - 172.16.1.72/30 — للفرع الأول
  - 172.16.1.68/30 — للفرع الثاني  
  - 172.16.1.64/30 — للفرع الثالث

### شبكة الخدمات الخارجية (السحابة الصفراء)
- شبكتين إنترنت مزودتين (ISP, ISP2) عبر شبكات نقطية منفصلة 
  (100.0.0.0/30, 200.0.0.0/30)
- شبكة خدمات داخلية (195.195.195.0/29) تحتوي:
  - Server-cisco.com
  - Server-PT DNS
- سويتش مركزي يربط الخوادم بالراوترات

## الخطوات
1. صممت الطوبولوجيا الكاملة: 3 فروع بأحجام مختلفة + شبكة خدمات 
   مركزية + اتصال بمزودي إنترنت (ISP)
2. طبّقت VLSM (Variable Length Subnet Masking) لتقسيم 172.16.0.0 
   بما يناسب عدد الأجهزة الفعلي بكل فرع (50، 62، 100 Host) بدل 
   تقسيم ثابت يهدر عناوين IP
3. خصصت شبكات نقطية (/30) منفصلة لكل رابط بين الراوترات لتوفير 
   العناوين
4. أعددت Static Routes يدويًا على كل راوتر لضمان وصول كل فرع 
   للفروع الأخرى وللخدمات المركزية (DNS)
5. اختبرت الاتصال بين الأجهزة عبر ping من فرع لآخر ومن الفروع 
   لخادم DNS
   ## ملاحظة
ملف Packet Tracer الأصلي (.pkt) لهذا المشروع تضرر ولم يعد قابلاً 
للفتح. التوثيق أعلاه مستند إلى لقطة الشاشة الأصلية للطوبولوجيا 
المكتملة، والتي توضح البنية والإعدادات النهائية بدقة.

## النتيجة
نجح الاتصال الكامل بين الفروع الثلاثة والخدمات المركزية عبر 
Static Routing، مع استخدام VLSM لتوزيع عناوين IP بكفاءة حسب 
الحجم الفعلي لكل فرع بدل تقسيم متساوٍ يهدر عناوين غير مستخدمة.
